# Policy Management

#### 1. Policy Function Overview

* The Policy menu consists of the following three sub-menus
  * [**License Policy**](policy-management.md#id-2.-license-policy)
  * [**Vulnerability Policy**](policy-management.md#id-5.-vulnerability-policy)
  * [**Asset Classification**](policy-management.md#id-7.-asset-classification)
* You can configure _**license policies**_ based on _**corporate standards**_.
* You can configure _**security vulnerabilities**_ based on the _**importance of the company's assets.**_



#### 2. License Policy Function

Navigating to the **Policy > License** Policy menu will display a list of license policies.

* The system provides three default license policies.

#### 2. License Policy Detailed Screen

* The License Policy detailed screen is primarily composed of the following 3 areas



**(1).  License Policy Meta-Information**

* It displays the policy information for the corresponding license policy. It shows the Policy Name, Policy Compliance Requirements, and whether it is a System Default Policy.

<div align="left"><figure><img src="../.gitbook/assets/license_policy_yellow1.png" alt="" width="563"><figcaption></figcaption></figure></div>





**(2). License Policy Item List**

In the License Policy Item List, you can view policy details configured for each stage.

1. Obligation Type Color
   1. You can set the color to be displayed when the corresponding **license policy stage** is met.
   2. When verified in a project, you can check the **Obligation Type** set in the project details screen.
2. License Use Approval
   1. Set whether to grant Approval, Disapproval, or Conditional Approval when this stage of the **license policy** is met.
3. Remark
   1. Write the compliance requirements for the corresponding **license policy stage**.
4. Priority is higher starting from Stage 1 in order.

<div align="left"><figure><img src="../.gitbook/assets/license_policy_yellow2.png" alt="" width="563"><figcaption></figcaption></figure></div>



**(2-1). Setting Attributes for License Policy Stages**

1. You can add attributes to the corresponding license policy stage using **drag-and-drop**.
2. If a component matches the attribute, it will be assigned to that license policy stage.

<div align="left"><figure><img src="../.gitbook/assets/image (17).png" alt="" width="563"><figcaption></figcaption></figure></div>





**(3). License Policy Rules Exception List**

* You can set exception license policies that override the **license policies** configured in the previous section (2)

#### 4. Editing/Deleting License Policies

* You can edit a policy by clicking the \[Edit License Policy] button on the License Policy detailed screen.
  * Only users with an account that has **License Policy Edit** permissions in their Role can edit license policies.([Refer to the Permission Configuration Method](user-role-management.md))
  * A license policy cannot be deleted if it is currently in use.

#### 5. Vulnerability Policy

Navigating to the **Policy > Vulnerability Policy** menu displays the vulnerability policies.

* This displays the default vulnerability policy information provided by the system.
* You can use **\[Import, Export]** to bring in or back up vulnerability policies.
* An internal **Vulnerability Grade** is generated by combining the **Importance Level** and **Severity** items.

<div align="left"><figure><img src="../.gitbook/assets/image (18).png" alt="" width="563"><figcaption></figcaption></figure></div>

* Vuln. Level: Information regarding the security vulnerability stage. There are four stages, from 1 to 4.
* Importance Level: The asset importance level configured in **Asset Classification**.
* Severity:
  * Information indicating the risk level of a vulnerability (CVE).
  * Higher risk levels are represented in the order of Critical, High, Medium, and Low.
  * This is the same concept as the Severity shown in the verification results during project verification.
* Vulnerability Grade: An internal security **vulnerability grade** generated by combining the Importance Level and Severity items.
* Whether to Use: Sets whether to use the vulnerability policy.
* Fulfillment Content: Used to write the compliance requirements that must be followed if a component falls under a specific security vulnerability grade.
* Action: Used to edit or delete policy items.



#### 6. Editing/Deleting Vulnerability Policies

You can edit a vulnerability policy by clicking the icon for the policy that requires modification.

* Only users with an account that has **Vulnerability Policy Edit** permissions in their Role can edit vulnerability policies.([Refer to the Permission Configuration Method](user-role-management.md))
* You can add a vulnerability policy using the **\[Add Vulnerability Level]** button.
* Clicking the **\[Reset]** button initializes the vulnerability policy to its default values.
* A vulnerability stage cannot be deleted if it is currently in use.



#### 7. Asset Classification

Navigating to the **Policy > Asset Classification** menu displays the asset classification list.

* This displays the default classification information provided by the system.
* It is displayed as the **Importance Level** in the Vulnerability Policy and is used to generate the internal **Vulnerability Grade** by combining it with Severity items.

<div align="left"><figure><img src="../.gitbook/assets/image (21).png" alt="" width="563"><figcaption></figcaption></figure></div>



Click the **\[Add Asset Classification]** button to add an asset classification in the screen below. Enter the mandatory Asset Classification Name and select the Asset Classification Stage. There are four asset classification levels available; select one and save.
